The copy holds every write the source committed before the call, like a crash point: state the source still holds in memory is not included, so call `saveState({ immediate: true })` in an action first to include it. The new actor runs `onFork` once at its first start instead of `createState` and `onCreate`. Both actors keep the copied schedule, queue and workflows, so each runs them. A fork is not idempotent: a key already held answers `actor.duplicate_key`. A database can be forked at most 16 times deep. The call answers once the copy finished. If its 30 second deadline passes after the new actor was created, it answers `actor.fork_pending` (504) with the new actor's ID in `metadata.actor_id`; the copy goes on, so read that actor later instead of forking again. If the deadline passes before the create was confirmed, it answers 500 `core.internal_error` with no actor ID, and the create may still land: retrying a keyless fork can then make a second copy, while retrying a keyed fork answers `actor.duplicate_key`. A source that never started has no database to copy and answers `actor.fork_failed` without creating anything. A namespace token needs `fork` on the source actor, by its ID or `any`, and `create` on every actor (`any`), since the new actor's ID is not known before the fork. The copy hands the caller everything the source holds, so no other operation, including `read`, allows a fork. The fork input comes from the caller: validate it in `onFork` like any client input. While an engine upgrade is rolling out, forks are refused with `actor.fork_unavailable` (503 with `Retry-After`) until every engine worker supports them; retry after the hinted delay. In a namespace upgraded from an earlier release, a keyed source that the upgrade has not yet moved into its namespace's volume group is refused with `guard.service_unavailable` (503 with `Retry-After`, reason `actor_moving`), since the move gives it a new actor ID that the copy's `forked_from` must name; retry after the hinted delay, and the fork is admitted once the source has moved.

```http
POST https://rivet.example.com/actors/{actor_id}/fork
```

### 409

`actor.duplicate_key`: a live actor already holds `key`, including an earlier fork of the same source. Forks are not idempotent. `actor.fork_too_deep`: the source's database is already 16 forks deep. `actor.fork_failed`: the database copy failed, for example because the source was destroyed during the fork, and the new actor was destroyed; or the source never started, so it has no database to copy, and nothing was created. `namespace.pending`, `namespace.archived`: the namespace does not accept new actors.
