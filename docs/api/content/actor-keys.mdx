Actors are identified by a name and a key. In RivetKit a key is an array of strings. The control plane endpoints under `/actors` accept and return the key as a single string in the `key` field, so a multi-part key has to be encoded before it goes on the wire.

## Encoding

Join the parts with `/`. Escape any literal `/` or `\` inside a part with a leading `\`.

| RivetKit key | Control plane `key` |
| --- | --- |
| `["my-counter"]` | `my-counter` |
| `["org-1", "room-2"]` | `org-1/room-2` |
| `["a/b"]` | `a\/b` |
| `["a\\b"]` | `a\\b` |
| `[""]` | `\0` |
| `[]` | `/` |

A keyless actor is encoded as `/`. Omitting `key` on [Create Actor](/docs/api/actors/create) or [Get or Create Actor](/docs/api/actors/get-or-create) means the same thing.

Escaping is what makes array keys safe to build from user data. `["org", "a/b"]` encodes to `org/a\/b`, which is a different actor from `["org", "a", "b"]` at `org/a/b`.

## Where keys appear

| Endpoint | Field |
| --- | --- |
| [List Actors](/docs/api/actors/list) | `key` query parameter, requires `name` |
| [Create Actor](/docs/api/actors/create) | `key` in the request body |
| [Get or Create Actor](/docs/api/actors/get-or-create) | `key` in the request body |
| Every actor response | `key` on the returned actor |

## Keys on gateway URLs

The gateway takes the key as one or more `rvt-key-part` query parameters, one occurrence per part: `rvt-key-part=org-1&rvt-key-part=room-2` is `["org-1", "room-2"]`. Each occurrence is a complete, independently percent-encoded part, so a part containing a comma, slash, or any other character is expressed exactly as given, with no escaping needed.

The gateway also accepts the legacy `rvt-key` parameter, which splits a single value on commas: `rvt-key=org-1,room-2` is `["org-1", "room-2"]`. This form cannot express a part that contains a comma, since it becomes indistinguishable from two separate parts. It is kept only for older clients; new clients should always send `rvt-key-part`. See [Actor Routing](/docs/api/actor-routing).
