Everything the RivetKit client does happens over HTTP. This reference documents those requests so you can call actors from any language, curl, or a platform without a Rivet SDK. Every endpoint page shows the raw request next to the equivalent TypeScript.

```http
https://rivet.example.com
```

Self-hosted deployments use the endpoint from your `RIVET_ENDPOINT` URL instead. See [Endpoints](/docs/endpoints).

## Two Surfaces

The API has two parts that use different authentication and addressing rules.

| | Gateway | Control plane |
| --- | --- | --- |
| Path prefix | `/gateway/{actor}/...` | `/actors`, `/auth/tokens`, ... |
| Purpose | Talk to a running actor: call actions, send HTTP requests, open realtime connections | Manage actors: list, create, destroy, sleep, and issue tokens |
| Authentication | `x-rivet-token` header, `{actor_id}@{token}` path, or `rvt-token` query | `Authorization: Bearer` header plus `namespace` query parameter |
| Safe from browsers | Yes, with a scoped token | No, requires your Rivet token |

Most applications only need the gateway. The RivetKit client resolves actors by name and key inline on each gateway request, so you rarely need to create actors or look up IDs through the control plane first.

## TypeScript to HTTP

| RivetKit client | HTTP |
| --- | --- |
| `client.counter.getOrCreate(["my-counter"]).increment(1)` | [`POST /gateway/counter/action/increment?rvt-method=getOrCreate&rvt-key=my-counter&...`](/docs/api/gateway/call-action) |
| `handle.fetch("/path", init)` | [`ANY /gateway/{actor}/request/path`](/docs/api/gateway/request) |
| `handle.connect()` | [`GET /gateway/{actor}/connect` (WebSocket)](/docs/api/gateway/connect) |
| `conn.increment(1)` | [`ActionRequest` message](/docs/api/gateway/connect#actions) |
| `conn.on("countChanged", cb)` | [`SubscriptionRequest` message](/docs/api/gateway/connect#events) |
| `handle.webSocket("/path")` | [`GET /gateway/{actor}/websocket/path` (WebSocket)](/docs/api/websockets) |
| `handle.resolve()` | [`PUT /actors`](/docs/api/actors/get-or-create) |
| `client.counter.create(["key"])` | [`POST /actors`](/docs/api/actors/create) |
| `handle.issueToken()` | [`POST /auth/tokens`](/docs/api/tokens/create) |

## When to Use HTTP Directly

- Calling actors from a language without a RivetKit client (Go, Ruby, PHP, shell scripts).
- Operational scripts that list, destroy, or sleep actors in bulk.
- Debugging: reproducing what the client sends with curl.

If you are writing TypeScript, Rust, Python, or Swift, use the client libraries instead. They handle actor resolution, retries, token refresh, and realtime connections for you. See [Clients](/actors/docs/clients).
