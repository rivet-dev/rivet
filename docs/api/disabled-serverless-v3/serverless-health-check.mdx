Metadata fetch failures are returned as a `failure` result in a successful HTTP response.

```http
POST https://api.rivet.dev/runner-configs/serverless-health-check
```

## Examples

<CodeGroup>

```bash cURL
curl -X POST "https://api.rivet.dev/runner-configs/serverless-health-check?namespace=$RIVET_NAMESPACE" \
  -H "Authorization: Bearer $RIVET_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://workers.example.com",
    "headers": {}
  }'
```

## Authentication

Send your namespace token as a bearer token in the `Authorization` header. Every control plane request also requires the `namespace` query parameter. See [Authentication](/docs/api/authentication).

## Query Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `namespace` | `string` | Yes | Name of the namespace to operate in. |

## Request Body

Content type: `application/json`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `headers` | `object` | No | Headers to include in the metadata request. |
| `url` | `string` | Yes | Serverless URL to probe. |

## Responses

### 200

A success result with the reported version or a failure result with error details.

```json
{
  "success": {
    "version": "<version>"
  }
}
```
