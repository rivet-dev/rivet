### What we'll build

- A `payments` Actor that gets a short-lived X.509 certificate from SPIRE, or an OIDC token from AWS IAM, when it starts.
- Renewal of the certificate or token before it expires, without dropping in-flight calls.
- Calls from the Actor to an internal service over mTLS, or with the token in a header.
- A check in the internal service that accepts only the identity of the Actor type it expects.

### Similar tools

This is the same job as SPIFFE and SPIRE, Istio service identity, or Teleport Workload Identity. On Rivet the identity would belong to the Actor type rather than to a pod, so many Actors on one worker can each prove what they are.

### Open questions

- Rivet has no workload identity support. The guide would attest the worker process, not the individual Actor, until Rivet can issue or vouch for per-Actor identities.
- Confirm how SPIRE node and workload attestation work when Actors run on serverless hosts where you do not control the node agent.
