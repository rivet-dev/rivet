What we'll build:

- A `cursorRoom` Actor per room, keyed by the room name, that every browser in the room connects to.
- Cursor presence stored per connection, so a cursor disappears the moment its tab closes.
- Text labels on the canvas that are saved in the Actor's SQLite database and survive restarts.
- A React client that sends its cursor on every mouse move and draws everyone else's.

<Steps>

<Step title="Install">

```sh
npm add rivetkit @rivetkit/react
```

</Step>

<Step title="Create the room Actor">

Each room is its own `cursorRoom` Actor. It keeps two kinds of data: the text labels, which belong to the room, and the cursors, which belong to whoever is connected right now:

<CodeSnippet file="examples/cursors/src/index.ts" title="index.ts" highlight="room,registry" />

- The `text_labels` table lives in the Actor's [SQLite](/actors/docs/sqlite) database. Every write is saved before the action returns, so labels are still there after everyone leaves and the Actor sleeps or restarts.
- `cursors` is a map in [vars](/actors/docs/state#ephemeral-state), keyed by [connection](/actors/docs/connections) ID. Each connection gets its own entry, and `onDisconnect` deletes it when the connection closes. Vars are never saved, and presence only means something while the user is connected, so stale cursors can never pile up in storage.
- `events` declares the four typed [events](/actors/docs/events) the room broadcasts. The React client gets the same payload types through `typeof registry`.
- The client picks the room with the [key](/actors/docs/keys) `[roomId]`. Two tabs with the same room name reach the same Actor, and different rooms never share cursors or labels.

</Step>

<Step title="Broadcast cursor moves">

`updateCursor` is the hot path. Every browser calls it on every mouse move:

<CodeSnippet file="examples/cursors/src/index.ts" title="index.ts" highlight="cursor" />

- It stores the cursor in `c.vars.cursors` under `c.conn.id`, the calling connection's ID, then broadcasts `cursorMoved` to every connection in the room, including the sender.
- The position is in a fixed 1920x1080 canvas space, not screen pixels. Each client scales the canvas to its window, so cursors line up across screen sizes.

<Warning>
The example sends an update on every raw `mousemove` and the Actor accepts all of them. A fast mouse on a high refresh rate display can send hundreds of updates per second per user. In production, throttle on both sides:

- **Client**: send the latest position every 33 to 50ms (20 to 30Hz) and drop the moves in between. Always send the final position so cursors settle where the mouse stopped, and interpolate between received positions when drawing.
- **Actor**: keep the time of the last accepted update per connection in `c.vars` and drop updates that arrive faster than your cap. A client throttle is only a courtesy, so the Actor is where the limit is enforced.
</Warning>

<Warning>
`userId` comes from the client. In the example it is a random string the browser makes up, so any client can send moves as another user. In production, key presence by `c.conn.id` or by a user id from [authentication](/guides/authentication), and clamp `x` and `y` to the canvas bounds.
</Warning>

</Step>

<Step title="Track who joins and leaves">

Presence has three moments: join, move, and leave. Move is `updateCursor`. Join and leave are these two:

<CodeSnippet file="examples/cursors/src/index.ts" title="index.ts" highlight="presence" />

- **Join**: there is no join broadcast. A new client calls `getRoomState` once after it connects to load the cursors and labels already in the room. Other users first see the newcomer on their first `cursorMoved`.
- `getRoomState` builds the cursor map from `c.vars.cursors`, which only holds live connections, instead of reading a stored list. The answer always matches who is connected. It reads the labels from SQLite.
- **Leave**: `onDisconnect` runs when a connection closes and removes that connection's cursor from `c.vars.cursors` and broadcasts `cursorRemoved` with it. Clients delete it from their map, so the cursor disappears as soon as the tab closes. See [Lifecycle](/actors/docs/lifecycle) for when `onDisconnect` runs.

</Step>

<Step title="Save text labels">

Clicking the canvas places a text label that everyone sees and that stays after the page reloads:

<CodeSnippet file="examples/cursors/src/index.ts" title="index.ts" highlight="labels" />

- `updateText` inserts or replaces a label by `id` in the `text_labels` table and broadcasts `textUpdated`. The client calls it on every keystroke, so others watch the text being typed.
- `removeText` deletes the label's row and broadcasts `textRemoved` with its id. The client calls it when the user presses Escape or finishes with an empty label.

<Warning>
Any client can edit or remove any label, because `updateText` trusts the `id` and `userId` it is given and `removeText` trusts the `id`. In production, check that the caller owns the label, cap the text length, and cap the number of labels so the table cannot grow without bound.
</Warning>

</Step>

<Step title="Connect the browser">

The React client connects with `useActor`, loads the room once, then keeps its maps up to date from events:

<CodeSnippet file="examples/cursors/frontend/App.tsx" title="App.tsx" region="client" highlight="connect,events,move" />

- `useActor({ name: "cursorRoom", key: [roomId] })` connects to the room's Actor and creates it if it does not exist yet. The room input defaults to `general`, and changing it reconnects to a different Actor.
- Once `cursorRoom.connection` is ready, the client calls `getRoomState` to seed `cursors` and `textLabels`. From then on, `useEvent` handlers apply `cursorMoved`, `cursorRemoved`, `textUpdated`, and `textRemoved` as they arrive.
- `handleMouseMove` converts the mouse position to canvas space and calls `updateCursor`. This is where a client throttle would go.
- The client draws its own cursor from the `cursorMoved` echo, labeled "you", so what a user sees is what everyone else sees.

</Step>

<Step title="Try it">

```sh
git clone https://github.com/rivet-dev/rivet.git
cd rivet/examples/cursors
pnpm install
pnpm dev
```

Open `http://localhost:5173` in two windows side by side. Move the mouse in one and its cursor moves in the other. Click the canvas, type, and press Enter to leave a label. Close one window and its cursor disappears from the other. Reload, and the labels are still there. Change the room name to get an empty canvas of your own.

</Step>
