What we'll build:

- A `rankedPlayer` Actor per username that stores the player's rating, wins, and losses.
- A `rankedMatchmaker` Actor that pairs players by rating and widens each player's search window the longer they wait.
- A `rankedMatch` Actor per duel that runs a 20 tick per second loop, checks movement, and resolves shots.
- Elo rating updates and a `rankedLeaderboard` Actor that keeps the top 20 players.

<Steps>

<Step title="Install">

```sh
npm add rivetkit@next
```

</Step>

<Step title="Create the matchmaker">

One `rankedMatchmaker` Actor, keyed `["main"]`, owns the queue. It stores waiting players in a `player_pool` table in its SQLite database and pairs them by rating:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/ranked/matchmaker.ts" title="matchmaker.ts" highlight="run-loop,queue,pairing" />

- The client only sends a username. The matchmaker reads the rating itself with `getRating` on that player's `rankedPlayer` Actor, so a client cannot queue with a made-up rating.
- Each player's window starts at 50 rating points and grows by 25 per second of waiting, up to 500. Two players match only if their difference fits inside both windows. The player who has waited longest is paired first, with the closest opponent that fits.
- `run` waits for the next queue message with a 2 second timeout. When nothing arrives, it runs `attemptPairing` anyway, because the windows keep growing while nobody new joins.
- Writes go through the queue, so `queueForMatch`, `unqueueForMatch`, and `matchCompleted` never interleave. `onDisconnect` removes a player who closes the tab.

A second loop, started with `c.waitUntil(...)`, sends every connection its own `queueUpdate` once a second. A queued player gets their wait time and current rating range. It uses `conn.send(...)` instead of `c.broadcast(...)` because each player gets different numbers.

</Step>

<Step title="Create the match">

When two players pair, the matchmaker creates a `rankedMatch` Actor with both usernames and ratings as input, then broadcasts `assignmentReady`. The match is a short realtime duel, first to 5 hits:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/ranked/match.ts" title="match.ts" highlight="tick,validate" />

- The match starts in `waiting` and switches to `live` in `onConnect` once both players are connected. A connection whose `username` param is not one of the two assigned players is dropped with `invalid_player`.
- `run` ticks every 50 ms (`TICK_MS`). Each tick checks the win condition and broadcasts a `snapshot`.
- The client owns its own movement and sends positions, so movement feels instant. `updatePosition` never trusts them: it caps the distance by `MAX_SPEED` times the time since the last update and clamps to the world bounds. A teleport turns into a normal step.
- Combat is decided on the server. `shoot` takes only a direction and checks range and angle against the server's positions, so a client cannot claim a hit.

<Note>
This is hybrid netcode: the client predicts its own movement and the server validates it, while hits and scores are server-authoritative. The duel only needs distance and angle checks. If your game needs real collisions, run a physics engine such as `@dimforge/rapier2d` inside the match and keep the client's copy for prediction only.
</Note>

</Step>

<Step title="Update ratings and the leaderboard">

When someone reaches the score limit, the match computes both new ratings and reports them to the matchmaker:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/ranked/match.ts" title="match.ts" region="elo" />

- `calculateElo` uses a K-factor of 32 with the ratings the players had when they were paired.
- `resultReported` makes sure the result is sent once, even though both the tick loop and `onDestroy` check it. If the match is destroyed without a winner, it sends an empty `matchCompleted` so the matchmaker still deletes the match's rows.

The matchmaker then writes the result to each player and to the leaderboard:

- `rankedPlayer` keeps the rating in `c.state`, keyed by username, so it outlives every match. `applyMatchResult` sets the new rating, counts the win or loss, and broadcasts `stateUpdate` to anyone watching that profile.
- `rankedLeaderboard` is one Actor keyed `["main"]`. The `updatePlayer` action only enqueues. The `run` loop upserts one row at a time into the `leaderboard` table, then broadcasts the top 20 as `leaderboardUpdate`.
- The leaderboard copies rating, wins, and losses from `getProfile`. The `rankedPlayer` Actor stays the source of truth.

<Warning>
Usernames are not authenticated in this example, so anyone can queue as any username and play on its rating. In production, key `rankedPlayer` by a user id from your sign-in and check it on connect with [authentication](/guides/authentication).
</Warning>

</Step>

The menu queues through the matchmaker and waits for an assignment. The game then connects to the match:

<CodeSnippet file="examples/multiplayer-game-patterns/frontend/games/ranked/menu.tsx" title="menu.tsx" region="queue" />

- `queueForMatch` returns the connection id. `waitForAssignment` ignores any `assignmentReady` for another connection, so two tabs with the same username do not both take the match. It also calls `getAssignment` once, in case the event fired before the listener was attached.
- The game connects with `params: { username }`, which is how `onConnect` finds the player.
- The local player moves every frame and sends `updatePosition` every 50 ms. When a `snapshot` puts the player more than 40 pixels away, the client snaps to the server's position. Other players are drawn with interpolation toward their last snapshot position.
- The game is drawn on a canvas with `requestAnimationFrame`. React state is only used for menus.

</Step>

<Step title="Try it">

```sh
git clone https://github.com/rivet-dev/rivet.git
cd rivet/examples/multiplayer-game-patterns
pnpm install
pnpm dev
```

Open `http://localhost:5173` and pick **Ranked**. Click **Queue for Match**, then **Add Bot** to queue a bot, or queue from a second tab with another username. While you wait, the queue panel shows your match window, such as `match window: ±75 (1125 - 1275)`, growing every second. Move with WASD and click to shoot. After someone reaches 5 hits, click **Leave**. The menu's leaderboard and your profile show the new ratings.

</Step>
