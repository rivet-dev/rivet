### What we'll build

- An `organization` Actor per org that stores members, teams, and the role each member has.
- Admin actions to invite members, create teams, and change roles.
- A `project` Actor per resource that asks the organization Actor whether the caller may run an action before it runs it.
- A faster path that checks role claims in the member's JWT, and when to use it instead of asking the organization Actor.

### Similar tools

This is the same job as WorkOS, Clerk Organizations, Auth0 Organizations, or Permit.io. On Rivet the membership and role data is one Actor per org, so a role change takes effect on the next check without waiting for a token to expire.
