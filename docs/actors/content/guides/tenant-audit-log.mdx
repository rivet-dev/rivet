### What we'll build

- A `tenant` Actor per tenant whose actions each append who did what, when, and to which record to an `audit_log` table in its SQLite database.
- An append-only table with no update or delete action, so entries cannot be changed after they are written.
- A `shipAuditLog` workflow that sends new entries to a SIEM in batches and retries until each batch is accepted.
- A `getAuditLog` action that lets tenant admins filter the log by user, action, and time range.

### Similar tools

This is the same job as WorkOS Audit Logs, Retraced, or Datadog Audit Trail. On Rivet each tenant's log lives in the same Actor that runs the actions, so an entry is written in the same place and at the same time as the change it records.
