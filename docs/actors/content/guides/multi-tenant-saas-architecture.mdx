### What we'll build

- A comparison of the three models: a shared schema with a `tenant_id` column, a schema per tenant, and a database per tenant.
- A `tenant` Actor per tenant with its own SQLite database, created when the tenant signs up.
- A `tenantDirectory` Actor that maps each tenant to its plan and settings.
- An API that verifies the session with a shared auth service and calls only the tenant Actor named in the verified token.
- Schema migrations that run per tenant as each tenant's Actor wakes.

### Similar tools

This is the same job as Supabase row-level security, Neon projects per tenant, Turso databases per tenant, or Nile. On Rivet a tenant's database lives inside the Actor that serves it, so isolation comes from the Actor key and idle tenants cost nothing while they sleep.
