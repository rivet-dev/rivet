### What we'll build

- A `device` Actor per device that stores the latest telemetry, the desired state, and a queue of pending commands.
- An MQTT bridge that forwards each device's messages to its Actor, plus a direct WebSocket option for devices that can hold one open.
- A dashboard that subscribes to a device's events and sees telemetry as it arrives.
- Commands sent from the dashboard that wait in the queue until the device reconnects.
- A schedule that marks a device offline when it misses its reporting window.

### Similar tools

This is the same job as AWS IoT Device Shadow, Azure Digital Twins, or Cloudflare Durable Objects used as device state. On Rivet the twin, the command queue, and the offline timer all live in one Actor per device, and an idle device's Actor sleeps until its next message.
