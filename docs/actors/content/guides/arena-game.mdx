What we'll build:

- An `arenaMatchmaker` Actor with one queue per mode (`1v1`, `ffa`, `duo`, and `squad`) that only creates a match once enough players are waiting.
- Teams assigned by the matchmaker before the match exists, or no teams for free-for-all.
- An `arenaMatch` Actor per match that waits for every player, then runs at 20 ticks per second until a side reaches 10 kills.
- Movement that the client owns and the server checks, and hits that only the server resolves.

<Steps>

<Step title="Install">

```sh
npm add rivetkit@next
```

</Step>

<Step title="Create the matchmaker">

One `arenaMatchmaker` Actor, keyed `["main"]`, holds a waiting pool per mode and builds full matches from it. The pool, matches, and assignments live in its SQLite database:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/arena/matchmaker.ts" title="matchmaker.ts" highlight="queue,fill-match" />

- `queueForMatch` is an action. It creates the `playerId`, records `c.conn.id`, and puts a message on the internal `queueForMatch` queue. It returns right away. The match arrives later as an event, because nobody knows how long the wait will be.
- `run` handles one queue message at a time, so two players joining at once can't both fill the last slot. Each entry goes into `player_pool`, the new counts go out as `queueUpdate`, and `fillMatch` runs once the mode reaches its `MODE_CONFIG` capacity.
- `fillMatch` takes the players who have waited longest and assigns teams by position (`idx % teams`, or `-1` for free-for-all). It creates the `arenaMatch` Actor with the roster as input, saves each row in `assignments`, and broadcasts `assignmentReady`.
- `onDisconnect` sends `unqueueForMatch`, so a player who closes the tab leaves the pool.

<Warning>
`assignmentReady` is broadcast to every client connected to the matchmaker, and the `playerId` in it is enough to connect as that player. In production, send each assignment only to its owner with `conn.send(...)` (the row already stores `conn_id`), and check a signed token in the match.
</Warning>

</Step>

<Step title="Create the match">

Each match is its own `arenaMatch` Actor, keyed by the match id. It starts with the full roster and goes live once everyone has connected:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/arena/match.ts" title="match.ts" region="connect" />

- `createState` seeds every assigned player from the input with their team, color, and a random spawn point. The roster is fixed, so `onConnect` doesn't need to ask the matchmaker. An id that isn't on the roster is disconnected with `invalid_player`.
- The match stays in `waiting` until every assigned player has a connection, then switches to `live`. Nobody starts a 4v4 with three players.
- A disconnect only clears the player's connection id. Their seat and score stay, so they can reconnect into the same match.

</Step>

<Step title="Validate movement and score hits">

The match runs a 20 tick per second loop, and checks every move and shot that arrives between ticks:

<CodeSnippet file="examples/multiplayer-game-patterns/src/actors/arena/match.ts" title="match.ts" highlight="tick,combat" />

- `interval(TICK_MS)` ticks every 50 ms, twice as often as the battle royale, because arena fights are short and close. Ticks are skipped until the match is `live`. Each live tick checks the win condition and broadcasts one `snapshot`.
- The client owns movement. `updatePosition` limits each move to `MAX_SPEED` times the time since the last update and keeps the player inside the world, so a client that teleports only moves as far as it could have run.
- The server owns combat. `shoot` skips teammates, finds the closest enemy within `SHOOT_RANGE` and `SHOOT_ANGLE` of the aim, gives the shooter a point, respawns the victim at a random spot, and broadcasts `shoot`.
- `checkWinCondition` ends a free-for-all when one player reaches `SCORE_LIMIT`, and a team match when a team's combined score does. When the match Actor is destroyed, `onDestroy` sends `matchCompleted` so the matchmaker deletes its row.

<Note>
For a Rocket League style match, the ball is shared by both teams, so simulate it on the server with `@dimforge/rapier3d` and let each client predict only its own car. Also limit how often each connection may call `updatePosition` and `shoot`. The example client sends positions at most 20 times per second.
</Note>

</Step>

The menu queues for a mode and waits for an assignment, then the game connects to the match:

- The menu keeps its matchmaker connection open while queued, because the assignment arrives as an event. `queueUpdate` drives the "players in queue" counter.
- `waitForAssignment` listens for `assignmentReady` with this player's id and also calls `getAssignment` once, in case the event fired before the listener was attached. `getAssignment` only returns a row whose `conn_id` matches the caller's connection.
- The game connects with `arenaMatch.get(...)` and `playerId` in `params`, the same id the matchmaker put on the roster.
- The client moves its own player every frame and sends `updatePosition` at most every 50 ms. If a `snapshot` puts it more than 40 pixels from where it thinks it is, it snaps to the server's position.

</Step>

<Step title="Try it">

```sh
git clone https://github.com/rivet-dev/rivet.git
cd rivet/examples/multiplayer-game-patterns
pnpm install
pnpm dev
```

Open `http://localhost:5173`, pick **Arena**, choose **FFA**, and click **Queue**. The counter shows `1/4` players in queue. Click **Add Bot** three times. The menu shows **Match Found!**, then the match goes live once all four players connect. Move with WASD and click to shoot. The first player to 10 kills wins. Pick **Duo** or **Squad** to see teams.

</Step>
