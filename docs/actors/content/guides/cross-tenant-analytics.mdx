### What we'll build

- A `tenant` Actor per tenant that writes a change event to an outbox table in the same transaction as each write.
- An `exportChanges` workflow that reads new events, loads them into BigQuery, ClickHouse, or Snowflake in batches, and marks them sent.
- A warehouse schema with a tenant id column, used only for analytics and never for serving.
- Dashboards that query across tenants in the warehouse without touching any tenant Actor.

### Similar tools

This is the same job as Fivetran, Airbyte, Neon logical replication, or Supabase ETL. On Rivet each tenant's data stays in its own Actor for serving, and the export copies only change events, so cross-tenant queries never run on the serving path.
