### What we'll build

- A Next.js app on Vercel with one route handler at `/api/rivet/[...all]` that forwards requests to Rivet.
- A `workspace` Actor per workspace that holds live state and persists it to its SQLite database.
- React components that connect with `useActor`, call actions, and update on events over a WebSocket.
- Background jobs on `c.schedule` that keep running after every browser tab is closed.
- Server components and route handlers that stay stateless, with no WebSocket server or job queue to run.

### Similar tools

This is the same job as Vercel with Pusher or Ably, Convex with Next.js, Supabase Realtime, PartyKit, or Liveblocks. On Rivet the realtime channel, the state, the storage, and the background jobs all belong to the same Actor, so there is no separate pub/sub service to keep in sync with your database.
