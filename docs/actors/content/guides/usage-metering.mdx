### What we'll build

- A `meter` Actor per tenant with a `recordUsage` action for tokens, tool calls, and seat changes.
- Running totals per meter and per billing period in the Actor's SQLite database.
- An `exportUsage` workflow, started by a schedule, that sends new usage to Stripe meter events and records what it sent so nothing is billed twice.
- An optional copy of the same usage to a warehouse for internal chargeback reports.

### Similar tools

This is the same job as Stripe Billing meters, Metronome, Orb, OpenMeter, or Lago. On Rivet each tenant's counter is one Actor, so increments are ordered and exact without a shared counter table or a streaming pipeline.

### Open questions

- Rivet has no built-in analytics or usage export. The guide writes the export workflow by hand.
