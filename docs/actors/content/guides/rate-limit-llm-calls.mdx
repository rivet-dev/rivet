### What we'll build

- An `llmLimiter` Actor per user or API key that holds a token bucket and the spend so far in its state.
- An `acquire` action that the route or agent calls before every LLM call, which answers allow or deny.
- A `recordUsage` action that adds the tokens and cost of each finished call to the user's spend.
- A cron job on each limiter that refills the bucket and resets spend at the start of each period.
- A `/chat` route that returns a `429` with a retry time when a user is over the limit.

### Similar tools

This is the same job as Upstash Ratelimit, Cloudflare AI Gateway rate limits, Vercel AI Gateway, Helicone, or OpenRouter. On Rivet each user's counter is a single Actor that handles one request at a time, so checks and updates do not race, and the limits can depend on anything stored in that Actor.

### Open questions

- Rivet has no built-in LLM gateway. Provider routing, failover between providers, and spend tracking across providers are left to your code or to a separate gateway.
