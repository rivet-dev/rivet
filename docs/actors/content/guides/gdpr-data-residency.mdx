### What we'll build

- A `user` Actor per user, created in the EU region for EU users and in the US region for US users.
- An API that stores each user's home region at sign-up and routes every request to the Actor in that region.
- User data kept only in the Actor's state and SQLite database, so it never leaves the region it was created in.
- An erasure endpoint that destroys the user's Actor, which deletes their state and database in one call.
- A check that a user cannot be served from the wrong region, even after a failover.

### Similar tools

This is the same job as choosing a region per project in Supabase or Neon, PlanetScale data residency, or Cloudflare Durable Objects jurisdictions. On Rivet the unit of residency is one user's Actor, so a single app can hold EU and US users side by side without a separate database per region.

### Open questions

- Rivet has no documented API to create an Actor in a chosen region and keep it there. The guide needs this, or it must deploy a separate Rivet per region.
- Rivet does not publish a data residency guarantee for Actor state, SQLite, or backups. Confirm what stays in region on Rivet Cloud and on self-hosted Rivet.
- Confirm that `destroy` deletes the Actor's SQLite data and any backups, so it counts as erasure under GDPR.
