<Warning>
`c.state` and `c.conn.state` were deprecated in 3.0 and will be removed in a future version. They still work today, so you can migrate at your own pace.
</Warning>

## What is deprecated

Earlier versions of Rivet Actors stored durable data in two places that Rivet saved for you:

- **Actor state** (`c.state`): a single serializable value defined with `state` or `createState`. Rivet wrote it to storage on a throttle and loaded it again on every start.
- **Connection state** (`c.conn.state`): a value per connection defined with `connState` or `createConnState`.

The related options `onStateChange`, `c.saveState()`, `stateSaveInterval` and `createConnStateTimeout` are deprecated with them.

The Rust SDK no longer has actor state or connection state APIs. Store durable data with `ctx.sql()` and in-memory data in fields on your actor struct.

Use these instead:

- **Durable data** goes in [SQLite](/actors/docs/sqlite) (`c.db`).
- **In-memory data** goes in [`c.vars`](/actors/docs/state#ephemeral-state). Load it from SQLite in `createVars` to serve reads from memory.
- **Connection data** is tracked from `onConnect` and `onDisconnect`. See [Connection state](#connection-state).

## Migrate actor state to SQLite

Move existing data with a SQLite migration. It reads the old state once, writes it into your own tables, and from then on the actor only uses SQLite.

1. Remove `state` or `createState` from the actor definition.
2. Add a `db` with an `onMigrate` that creates your tables and copies the old state into them.
3. Load the data into `c.vars` in `createVars` and write changes back to SQLite in your actions.

### Where the old state lives

Actor state is stored in the actor's SQLite database in a table managed by Rivet. This table and its data will never be dropped, even after `c.state` is removed, so you can migrate out of it at any point:

```sql
CREATE TABLE _rivet_actor_state (
    id    INTEGER PRIMARY KEY CHECK (id = 1),
    state BLOB NOT NULL
) STRICT
```

- There is at most one row, with `id = 1`. An actor that never had state may have no row or an empty blob.
- `state` is the value of `c.state` encoded as [CBOR](https://cbor.io). `BigInt`, `Uint8Array`, `ArrayBuffer`, `Set` and `undefined` are stored as two-element arrays such as `["$BigInt", "42"]`. `decodeLegacyState` above turns them back into their original types. This tag encoding applies to TypeScript actors.
- Only read from `_rivet_*` tables. Do not write to or drop them; Rivet manages them.

### Hibernatable WebSockets

A [hibernatable WebSocket](/actors/docs/websocket-handler#websocket-hibernation) stays open while the actor sleeps, and `c.vars` is rebuilt when it wakes. Store data for these connections in SQLite so it survives, and delete it in `onDisconnect`.
