## Connection State

Track per-connection data in [`c.vars`](/actors/docs/state#ephemeral-state), keyed by `conn.id`. Add it in `onConnect` and remove it in `onDisconnect`. For data that must outlive the actor's memory, such as on a hibernatable WebSocket, store it in [SQLite](/actors/docs/sqlite) instead.

## Connection Lifecycle

Each client connection goes through a series of lifecycle hooks that allow you to validate, initialize, and clean up connection-specific resources.

**On Connect** (per client)

- `onBeforeConnect`
- `onConnect`

Pending connections are not visible in `c.conns` while `onBeforeConnect` is running. RivetKit adds the connection to `c.conns` after it succeeds and before `onConnect` runs.

**On Disconnect** (per client)

- `onDisconnect`

### `onBeforeConnect`

The `onBeforeConnect` hook is called whenever a new client connects to the actor. Can be async. Clients can pass parameters when connecting, accessible via `params`. This hook is used for connection validation and can throw errors to reject connections.

The `onBeforeConnect` hook is used solely for validation. To keep per-connection data, store it in `c.vars` from `onConnect`.

Connections are not visible in `c.conns` while `onBeforeConnect` is running.

Connections cannot interact with the actor until this method completes successfully. Throwing an error will abort the connection. This can be used for authentication, see [Permissions](/actors/docs/permissions) for details.

### `onConnect`

Executed after the client has successfully connected. Can be async. Receives the connection object as a second parameter.

By the time `onConnect` runs, the connection is visible in `c.conns`.

## Connection List

All active connections can be accessed through the context object's `conns` property. This is a `Map<string, Conn>` of all current connections, keyed by connection ID.

This is frequently used with `conn.send(name, event)` to send messages directly to clients. To send an event to all connections at once, use `c.broadcast()` instead. See [Events](/actors/docs/events) for more details on broadcasting.

</Note>
