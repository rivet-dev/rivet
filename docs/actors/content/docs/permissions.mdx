Permissions are enforced inside your actor, on a caller that has already reached it. This is the only layer that can see the actor's own data, `c.key`, and action arguments, so every domain rule lives here.

The layer above it decides which actor a client may reach at all. See [Authentication](/docs/authentication) for that, and [JWTs](/docs/jwt) to scope a client to a single actor before it ever gets here.

## Identifying the Caller

`onBeforeConnect` runs before a connection is usable. It can be async, and throwing from it rejects the connection.

### `onBeforeConnect`

Use it for pass or fail validation. When actions need the caller's identity later, resolve it again in `onConnect` and store it in `c.vars` keyed by `conn.id`, as in the [Quickstart](#quickstart).

<CodeSnippet file="examples/docs/actors-permissions/on-before-connect.ts" />

### Available Data

`onBeforeConnect` can read:

| Property | Description |
| --- | --- |
| `params` | Data the client passed when connecting. See [connection params](/actors/docs/connections#parameters). |
| `c.request` | The underlying HTTP request. |
| `c.request.headers` | Request headers. Not available for `.connect()`. |
| `c.key` | The actor's key. See [keys](/actors/docs/keys). |

Prefer `params` over `c.request.headers`. It works for both HTTP and WebSocket connections, while headers do not.

## Permission Surfaces

Authorization is explicit per surface. Nothing is checked implicitly.

- `onBeforeConnect` rejects unauthenticated connections.
- Action handlers enforce per-action rules.
- `events.<name>.canSubscribe` allows or denies an event subscription.

<CodeSnippet file="examples/docs/actors-permissions/chat-room.ts" />

### Fail by Default

1. Keep connection hooks strict and reject invalid credentials.
2. In each action, allow the expected roles explicitly and throw `forbidden` otherwise.
3. In `canSubscribe`, return `true` only for allowed roles and end with `return false`.

### Return Value Contract

`canSubscribe` must return a boolean. `true` allows, `false` denies with `forbidden`. Returning `undefined`, `null`, or any non-boolean throws an internal error.

`canSubscribe` applies only to event names declared in `events`, and broadcasting an undeclared event still reaches its subscribers.

## When You Need Less of This

If you scope each user's [JWT](/docs/jwt) to a single actor, that actor has exactly one participant and needs little authorization of its own. These hooks earn their keep once an actor is shared, as in a chat room or a per-tenant database.
