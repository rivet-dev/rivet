## Do You Need Authentication?

<Tabs>
<Tab title="Rivet Cloud">
	Actors are private by default on Rivet Cloud. Only requests with the publishable token can interact with actors.

	- **Backend-only actors**: If your publishable token is only included in your backend, then authentication is not necessary.
	- **Frontend-accessible actors**: If your publishable token is included in your frontend, then implementing authentication is recommended.
</Tab>
<Tab title="Self-Hosted">
	Control plane authentication is required by default on self-hosted Rivet. Configure an admin token on the control plane and issue scoped tokens for clients.

	See [Authentication](/docs/authentication) for credentials and [Scoped Tokens](/docs/jwt) for permissions.
</Tab>
</Tabs>

## Issue access tokens

Keep the control plane's admin credential on your backend. Issue [scoped tokens](/docs/jwt) for clients, granting only the resources and operations they need in their namespace. Actor traffic uses `actor_gateway` permissions; Actor creation and lookup use `actor` permissions.

Control plane grants decide which Actors a client can reach. The connection hooks below can also check your application's user identity and permissions.

## Authentication Connections

Authentication is configured through `onBeforeConnect`, which validates credentials and rejects the connection by throwing. To use the caller's identity in actions, store it in `c.vars` keyed by `conn.id` from `onConnect`, then look it up with `c.conn.id`.

## Access Control

After a connection is authenticated, use [Access Control](/actors/docs/access-control) to enforce authorization:

- Check permissions in action handlers.
- Use `events.<name>.canSubscribe` to gate event subscriptions.

## Available Auth Data

Authentication hooks have access to several properties:

| Property | Description |
|----------|-------------|
| `params` | Custom data passed by the client when connecting (see [connection params](/actors/docs/connections#parameters)) |
| `c.request` | The underlying HTTP request object |
| `c.request.headers` | Request headers for tokens, API keys (does not work for `.connect()`) |
| `c.key` | The actor's key (see [keys](/actors/docs/keys)) |

It's recommended to use `params` instead of `c.request.headers` whenever possible since it works for both HTTP & WebSocket connections.
