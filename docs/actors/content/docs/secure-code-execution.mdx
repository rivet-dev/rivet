Agents write code, and that code should not run in your process. An Actor can boot a lightweight VM with its own filesystem, shell, and JavaScript and Python runtimes, and run the code there. The VM boots in milliseconds inside the Actor's process, so there is no separate sandbox service to deploy. The VM is powered by [agentOS](/agentos/docs).

There are two ways to use it:

- **A VM per Actor.** The VM lives as long as the Actor, so an agent session keeps its files and processes between runs.
- **A temporary VM.** Boot a VM for one evaluation and release it when the call ends.

### More

- [Networking](/agentos/docs/networking): run servers inside the VM and reach them from the Actor.
- [Software](/agentos/docs/software): install packages and tools into the VM.
- [Schedules](/agentos/docs/cron): run commands in the VM on a cron schedule.
- [Permissions](/agentos/docs/permissions) and [resource limits](/agentos/docs/resource-limits): control network access and cap CPU, memory, processes, and filesystem size.

## Persistence

The VM's filesystem is in memory and is released with the VM. Keep anything that must outlive a wake cycle in the Actor's [state](/actors/docs/state) or [SQLite](/actors/docs/sqlite), or store the VM's filesystem durably with [agentOS persistence](/agentos/docs/persistence).
