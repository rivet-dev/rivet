This page documents the limits for Rivet Actors.

There are two types of limits:

- **Soft Limit**: Application-level limit, configurable in RivetKit. These cannot exceed the hard limit.
- **Hard Limit**: Infrastructure-level limit that cannot be configured.

## Limits

### WebSocket

These limits affect actions that use `.connect()` and [low-level WebSockets](/actors/docs/websocket-handler).

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Max incoming message size | 64 KiB | 16 MiB | Maximum size of a message from the client. The soft limit applies to `.connect()` messages and to HTTP action request bodies, not to low-level WebSockets. Soft limit configurable via `maxIncomingMessageSize`. |
| Max outgoing message size | 1 MiB | 16 MiB | Maximum size of a message to the client. The soft limit applies to `.connect()` messages and to HTTP action responses, not to low-level WebSockets. Soft limit configurable via `maxOutgoingMessageSize`. |
| Max WebSocket frame size | N/A | 16 MiB | Maximum size of a single WebSocket frame accepted by Rivet's transport edge. This is not configurable by browser clients and is not negotiated during the WebSocket handshake. |
| WebSocket open timeout | N/A | 15 seconds | Time allowed for Rivet to route the connection and start the actor. The `onBeforeConnect` hook runs after this and has its own timeout. |
| Keepalive ping interval | N/A | 30 seconds | Rivet pings each client WebSocket at this interval so proxies do not close idle connections. A missed pong does not close the connection. |

WebSocket connections close when the actor sleeps. Clients reconnect, which wakes the actor. An actor does not sleep from inactivity while it has open connections.

### HTTP

These limits affect actions that do not use `.connect()` and [low-level HTTP requests](/actors/docs/request-handler).

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Actor wake timeout | N/A | 45 seconds | Maximum time a request waits for its actor to be routed and started before it fails. Only relevant if something is wrong with starting actors. |
| Max queued requests per actor | N/A | 1,024 | Maximum requests waiting for one actor, mostly while it starts. Further requests fail with `envoy.actor_overloaded`. |
| Max buffered response body size | N/A | 16 MiB | Maximum size of a response whose body is sent in one piece, including headers. Streaming responses have no size limit and are flow controlled instead of buffered in full. |

Request bodies for [low-level HTTP requests](/actors/docs/request-handler) are streamed to the actor and have no fixed size limit. HTTP action request bodies are limited by `maxIncomingMessageSize`.

### Actor Storage

Each Rivet Actor has one durable volume that holds its [SQLite database](/actors/docs/sqlite). There is no fixed limit on the total storage of an actor.

### Actor SQLite Storage

These limits apply to the [SQLite database](/actors/docs/sqlite).

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Max pages changed per transaction | N/A | 32,768 pages (128 MiB) | Maximum SQLite pages one transaction can change, at 4 KiB per page. A larger transaction fails with `sqlite.transaction_too_large` and is rolled back; the database stays usable. |
| Transaction deadline | 60 seconds | N/A | Safety backstop for `db.transaction()`. Configure per transaction with `{ timeout: milliseconds }`; there is no product-level maximum. |
| Transaction coordinator queue | N/A | 128 operations | Maximum admitted SQLite operations waiting behind an active coordinated transaction. Additional operations fail with `sqlite.transaction_queue_full`. |

Large commits are sent in internal chunks, but each transaction is published atomically. The limit counts raw pages changed.

If a transaction fails with `sqlite.transaction_too_large`, split the work into smaller transactions, for example by inserting, updating, or deleting rows in batches. `VACUUM` rewrites the whole database in one transaction, so it runs only while the database's in-use pages fit under this limit; it is refused up front on larger databases. Building an index on a large table can also exceed the limit.

### Names and Keys

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Max actor key total size | N/A | 1,024 bytes | Maximum total size of the serialized actor key string. |
| Max actor name length | N/A | 64 bytes | Maximum length of an actor name. |
| Max namespace and pool name length | N/A | 63 bytes | Namespace and pool names are DNS labels: lowercase letters, digits, and hyphens. |

### Timeouts

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Action timeout | 60 seconds | N/A | Timeout for RPC actions. Configurable via `actionTimeout`. |
| Raw HTTP response start timeout | 60 seconds | N/A | Time allowed for a raw `onRequest` handler to return its response. Configurable via `actionTimeout`. A streaming response has no fixed total-duration timeout after it starts. |
| Raw HTTP stream idle timeout | N/A | None | Rivet does not close a stream for producing no chunks. Other proxies may, so send SSE heartbeats. |
| On before connect timeout | 5 seconds | N/A | Timeout for the `onBeforeConnect` hook. Configurable via `onBeforeConnectTimeout`. |
| Create vars timeout | 5 seconds | N/A | Timeout for `createVars` hook. Configurable via `createVarsTimeout`. |
| On connect timeout | 5 seconds | N/A | Timeout for `onConnect` hook. Configurable via `onConnectTimeout`. |
| On migrate timeout | 30 seconds | N/A | Timeout for `onMigrate` hook. Configurable via `onMigrateTimeout`. |
| Sleep grace period | 15 seconds | N/A | Total graceful shutdown budget for both sleep and destroy. Covers `onSleep`/`onDestroy`, `run` workflow shutdown, `waitUntil`, `keepAwake`, async raw WebSocket handlers, and connection cleanup. Configurable via `sleepGracePeriod`. |
| Sleep timeout | 30 seconds | N/A | Time of inactivity before actor hibernates. Configurable via `sleepTimeout`. |

### Actor Lifecycle

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Actor start threshold | N/A | 30 seconds | Maximum time for an actor to report running after its start is sent before the start is given up and retried. |
| Actor stop threshold | N/A | 30 seconds | Time a node is given to stop its actors once asked. RivetKit uses it as the default `shutdown.gracePeriodMs` for draining the whole process; each actor's own budget is `sleepGracePeriod`. A stop that goes unanswered for about 45 seconds is treated as lost. |

### Forks

See [Forking](/actors/docs/forking).

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Max fork depth | N/A | 16 forks | Maximum forks behind one actor, counting forks of forks. Forking an actor that is already 16 forks deep fails with `actor.fork_too_deep`. |
| Fork call deadline | N/A | 30 seconds | Time a fork call waits for the copy. Past it, the call fails with `actor.fork_pending` and the new actor's ID in `metadata.actor_id`, and the copy goes on. |
| `onFork` timeout | N/A | 5 seconds | Time `onFork` has to finish on the native runtime. A throw or timeout fails the start, and `onFork` runs again on the next start. |
| Fork first start | N/A | 15 seconds | Time a fork's first start has to run `onMigrate`, `createVars`, and `onFork` and save the result. Past it, the start fails and `onFork` runs again. On the WebAssembly runtime this is the only limit on `onFork`. |
| Max `onFork` writes | N/A | 32,768 pages (128 MiB) | On the native runtime, every SQLite change `onFork` makes is saved in one commit with the fork. More fails the start; move a large backfill into a later action. |
| Max namespace fork depth | N/A | 3 forks | A namespace can be forked, and its fork forked again, down to 3 levels below the original. A deeper fork fails with `namespace.lineage_too_deep`. |
| Namespace fork call deadline | N/A | 30 seconds | Time a namespace fork call waits for the fork to go live. Past it, the call answers with the namespace as it stands; poll `GET /namespaces?name=` until it is `live`. |

### Tokens

See [Scoped Tokens](/docs/jwt).

| Name | Soft Limit | Hard Limit | Description |
|------|------------|------------|-------------|
| Max operations per grant | N/A | 6 | One grant can allow each of `create`, `read`, `update`, `delete`, `list`, and `fork` once. |

## Increasing Limits

These limits are sane defaults designed to protect your application from exploits and accidental runaway bugs. If you have a use case that requires different limits, [contact us](/talk-to-an-engineer/) to discuss your requirements.
