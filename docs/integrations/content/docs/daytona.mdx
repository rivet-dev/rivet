[Daytona](https://daytona.io) runs sandboxes created from snapshots, with a stop-and-start lifecycle that keeps the filesystem between runs. Through `@rivet-dev/sandbox-adapter`, each Actor creates a Daytona sandbox, runs commands and uses files in it, stops it while the Actor sleeps, and deletes it when the Actor is destroyed.

## Quickstart

<Steps>

<Step title="Install">

```sh
npm install rivetkit @rivet-dev/sandbox-adapter @daytonaio/sdk
```

</Step>

<Step title="Configure Daytona">

Create an API key in the [Daytona dashboard](https://app.daytona.io) and put it in `.env`. It stays on the node and never enters the sandbox.

```sh title=".env"
DAYTONA_API_KEY=
```

</Step>

## Options

| Option | Description |
| --- | --- |
| `client` | A Daytona client. Defaults to `new Daytona()`, which reads `DAYTONA_API_KEY`. |
| `create` | Options for Daytona's `create`, such as the snapshot. |

The working directory is the sandbox's own working directory. `suspend` stops the sandbox while the Actor sleeps, and `connect` starts it again the next time the Actor uses it. `destroy` deletes it. Daytona returns stdout and stderr together in `stdout`, leaves `stderr` empty, and calls `onData` once when the command ends.

The `Sandbox` API, lifecycle, and the other providers are in the [sandbox adapter guide](/guides/sandbox-adapter).
