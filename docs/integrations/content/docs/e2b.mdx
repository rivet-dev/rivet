[E2B](https://e2b.dev) runs cloud sandboxes from templates you define, and starts one in a few hundred milliseconds. Through `@rivet-dev/sandbox-adapter`, each Actor creates an E2B sandbox, runs commands and uses files in it, pauses it while the Actor sleeps, and deletes it when the Actor is destroyed.

## Quickstart

<Steps>

<Step title="Install">

```sh
npm install rivetkit @rivet-dev/sandbox-adapter e2b
```

</Step>

<Step title="Configure E2B">

Create an API key in the [E2B dashboard](https://e2b.dev/dashboard) and put it in `.env`. It stays on the node and never enters the sandbox.

```sh title=".env"
E2B_API_KEY=
```

</Step>

## Options

| Option | Description |
| --- | --- |
| `template` | Template name or id. Defaults to `base`. |
| `create` | Options for E2B's `Sandbox.create`. The API key defaults to `E2B_API_KEY`. |
| `cwd` | Working directory inside the sandbox. Defaults to `/home/user`. |

E2B ends a sandbox when its timeout runs out, so the provider creates sandboxes that pause on timeout and resume on the next call. `suspend` pauses the sandbox while the Actor sleeps, and `destroy` deletes it. After a timeout, `exec` returns empty `stdout` and `stderr`; `onData` has already received the output.

The `Sandbox` API, lifecycle, and the other providers are in the [sandbox adapter guide](/guides/sandbox-adapter).
