`@rivet-dev/pi` runs one [Pi](https://github.com/earendil-works/pi) coding-agent session per Rivet Actor. The conversation is stored in the actor's SQLite database and restored on wake.

## Quickstart

<Steps>

<Step title="Install">

```sh
npm install @rivet-dev/pi rivetkit
```

</Step>

<Step title="Define the actor">

</Step>

</Step>

</Steps>

## Actions

Actions use Pi's `AgentSession` method names and arguments, for example `steer`, `followUp`, `abort`, `compact`, `setThinkingLevel`, `executeBash`, `getMessages`, and `getSession`.

## Sandboxes

Pi's file and shell tools run only in a sandbox. Without one, Pi has no file or shell tools, only the `customTools` you pass, and never touches the actor host.

The actor stores the sandbox id and reconnects to it on wake. If a sandbox fails, the tool call fails.

Run the tools in an [agentOS](https://rivet.dev/agentos) VM:

```ts
import { agentOS, setup } from "@rivet-dev/agentos";
import { pi } from "@rivet-dev/pi";
import { agentOSProvider } from "@rivet-dev/sandbox-adapter/agentos";

const vm = agentOS();
const agent = pi({ sandbox: agentOSProvider({ actor: "vm" }) });

export const registry = setup({ use: { agent, vm } });
```

Or in a hosted sandbox such as E2B, Daytona, or Modal through [sandbox-agent](https://github.com/rivet-dev/sandbox-agent):

```ts
import { pi } from "@rivet-dev/pi";
import { sandboxAgentProvider } from "@rivet-dev/sandbox-adapter/sandbox-agent";
import { e2b } from "sandbox-agent/e2b";

const agent = pi({ sandbox: sandboxAgentProvider(e2b()) });
```

To use another environment, implement `SandboxProvider` from `@rivet-dev/sandbox-adapter`.
